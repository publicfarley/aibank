Siri → aiBank → sign in → back to Siri

How aiBank lets Siri start a banking task while the app is closed, bring the app forward so the person can sign in, and hand the rest of the request back to Siri. Covers the APIs involved and what is built on branch siri-snippets.

Is it possible?
Yes

iOS 26 added foreground continuation: a tool runs in the background and comes to the foreground only when it has to, then keeps running.

Is it built?
Yes

Every tool that reads or moves money uses the hand-off (SignInGate.swift). The skills tell Siri to start with Get Accounts, so the sign-in happens before Siri looks up a contact or payee.

1 · The pieces

Siri doesn't know anything about signing in. It calls a tool, which is an @AppIntent(.tool). The App Intents runtime launches aiBank in the background to run the tool. The bank server decides whether a session exists. If it doesn't, the tool's afterSigningIn gate brings the app forward on the normal sign-in screen. Then it waits on the AppStore until the person is signed in, and runs the work again.

2 · "Send Sam $25" with the app closed and signed out

Step 1 of the send-etransfer skill tells Siri to call Get Accounts first every time, even when the person names an account. If there's no session, that call is the one that comes forward for sign-in. After that the server session is live, so Siri's lookup of "Sam" and the e-Transfer itself go through.

Why Get Accounts has to come first. Before any tool's perform() runs, the runtime looks up its entity parameters, such as recipient through RecipientQuery.entities(for:). A query can't bring the app forward. If Siri called Send e-Transfer with no session, that lookup would throw "Please sign in to aiBank first." and end the request. Get Accounts takes no entities, so it can always reach its sign-in gate. The skill text is guidance to Siri's model, not a guarantee, and it still needs checking on a device.
A second safety net. Send e-Transfer, Pay Bill and Get Recent Transactions also have the gate. If the 30-minute session ends between Get Accounts and the next tool call, the tool's first reads come back with no session, the app comes forward for sign-in, and the reads run again. The transfer itself is never retried, and it still comes after the review card.

3 · The gate, step by step

func afterSigningIn<T: Sendable>(store: AppStore, reason: String,
                                 _ work: @Sendable () async throws -> T) async throws -> T {
    do {
        return try await work()
    } catch let error as BankError where error == .notSignedIn || error == .sessionExpired {
        guard systemContext.currentMode.canContinueInForeground else {
            throw needsToContinueInForegroundError("Open aiBank and sign in to \(reason).")
        }
        await store.send(.serverEndedSession(error, now: .now))
        try await continueInForeground("Sign in to aiBank to \(reason).", alwaysConfirm: false)
        try await store.waitUntilSignedIn()
        return try await work()
    }
}

4 · Two different locks

People often mix these up. A money-moving request from Siri passes both, and they are separate.

Device lockBank session
What proves itFace ID, Touch ID or passcodeCard number + password on SignInView
Who enforces itThe system, before perform()The bank server, on every request (requireSession())
Declared bystatic let authenticationPolicyNothing declarative. The tool catches .notSignedIn / .sessionExpired
aiBank setting.requiresAuthentication for reads, .requiresLocalDeviceAuthentication for e-Transfer and Pay Bill30 minutes idle (sliding). Ends on Sign Out or after 30 min in the background. Lasts across app launches on the server
Effect on SiriSiri asks to unlock or authenticate itself, and the app isn't involvedThe app has to come forward, which is the hand-off on this page

Because the server keeps the session across launches, "app closed" doesn't always mean "signed out". If the person used aiBank in the last 30 minutes and didn't sign out, every tool runs in the background and the app never opens.

6 · APIs involved

@AppIntent(.tool)

AppIntents · iOS 27 · Intents.swift

Exposes an intent to Siri's model as a callable tool. The model chooses the tool from its title, description and parameter descriptions.

Skills.skillsbundle / SKILL.md

iOS 27 · send-etransfer/SKILL.md

The procedure Siri follows for a task. Step 1 of the e-Transfer and Pay Bill skills is "start with Get Accounts". That's what gets the person signed in before Siri looks up a contact or payee.

supportedModes: IntentModes

AppIntents · iOS 26

[.background, .foreground(.dynamic)]: start without UI and come forward only if the code asks. Replaces the deprecated openAppWhenRun.

static var supportedModes: IntentModes {
    [.background, .foreground(.dynamic)]
}

continueInForeground(_:alwaysConfirm:)

AppIntents · iOS 26 · SignInGate.swift

Brings the app forward partway through perform() and keeps running. alwaysConfirm: false skips the extra "continue in app?" prompt. It throws in a context that can't show the app.

systemContext.currentMode.canContinueInForeground

AppIntents · iOS 26

False in voice-only places such as CarPlay and AirPods on the go. The gate checks it first.

needsToContinueInForegroundError(_:)

AppIntents · iOS 26

The fallback when the app can't come forward. Throwing it has the system tell the person to open aiBank, instead of showing a plain failure.

authenticationPolicy

AppIntents · IntentAuthenticationPolicy

The device lock. .requiresLocalDeviceAuthentication asks for Face ID or passcode before any money-moving tool runs, even on an unlocked phone.

@Dependency + AppDependencyManager

AppIntents · AIBankApp.init

A cold launch runs App.init, which registers BankClient and the same AppStore the UI uses. That's how the tool can watch the UI's sign-in.

Observations { … }

Observation · Swift 6.2 · waitUntilSignedIn()

An async sequence over an @Observable value. The tool suspends on store.state.session.session != nil with no polling. The loop ends with CancellationError if Siri gives up.

requestConfirmation(actionName:dialog:snippetIntent:)

AppIntents · iOS 26 snippet form

Shows the review card just before money moves. Saying no throws and stops the tool. Everything before it is safe to run again, because perform() can restart.

AppFeature.Action.serverEndedSession

AIBankCore · pure reducer

If the app is on screen and still shows signed in, this drops it to the sign-in screen so the hand-off lands there. Covered by ReducerTests.

EnumerableEntityQuery

AppIntents · Entities.swift

Resolves RecipientEntity / AccountEntity / PayeeEntity before perform() runs. This is where the gap is: a query can't call continueInForeground.

7 · How e-Transfer stays reliable

Siri looks up "Sam" before SendETransferIntent.perform() runs, and that lookup can't bring the app forward. So the sign-in has to happen before the lookup. Two layers make sure it does: the skill orders the tool calls, and the gate in each tool covers a session that ends partway through.

On the simulator, the app builds with no warnings, all 51 package tests and 4 app tests pass, and sirimetadataanalyzer reports 0 errors and 0 warnings. Its one suggestion is SMA701: the e-Transfer tool looks like Send Message. A test case below checks whether Siri confuses the two. The gate is app code that needs Siri, so it's tested on a device, not in unit tests.

8 · Test Cases

Run these on a real iPhone. The simulator can't open Siri.

  • Signed out: "What are my balances in aiBank". Does the app come forward, and does the answer appear back in Siri after sign-in?
  • A slow manual sign-in (30+ seconds). Does the intent time limit end it while it waits?
  • Hands-free (CarPlay or AirPods): do we get the "Open aiBank and sign in…" prompt?
  • "Send Sam $25" and "Send Sam $25 from chequing", signed out with the app closed. Does Siri call Get Accounts first in both cases, as the skill says?
  • "Send Sam $25": does Siri pick the e-Transfer tool, not Messages (SMA701)?
  • "Pay my phone bill $42.50", signed out. Same check for the Pay Bill skill.
  • Review card left open past 30 minutes, then Send. The send isn't gated, so expect "Your session has expired. Please sign in again." with no money moved, and check that Siri doesn't retry it on its own.
